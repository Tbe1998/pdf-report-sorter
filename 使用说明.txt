PDF 日志分拣助手  v1.2.3
================================

一句话：你在某个文件夹里打印 PDF 日报，它等文件彻底写完，
再根据文件名自动判断是哪个项目的，把文件移动到那个项目的文件夹里。

  地铁1号线停车场监测日报2026-10-31.pdf
      → D:\监测日报\地铁1号线停车场\
  城西路隧道监测日报2026-10-31.pdf
      → D:\监测日报\城西路\

【第一次使用】

  1. 双击「PDF文件夹搬运助手.exe」（不需要安装任何东西）。
  2. ① 源文件夹：选 PDF 打印机保存文件的文件夹（比如 D:\待分拣）。
  3. ② 默认目标文件夹：规则都没命中时用它，可以留空（留空=留在源文件夹不动）。
  4. ③ 点「编辑规则」，按里面的示例写你的项目和文件夹，保存。
  5. ④ 建议在"只处理包含"里填「日报」，这样合同、图纸之类的 PDF 不会被误搬。
  6. 点「开始分拣」。

  想让它一直在后台干活：点右上角 × 就会收进系统托盘（右下角时钟旁边），
  程序继续在后台分拣；双击托盘图标重新打开窗口，右键托盘图标可以退出。
  界面上也有「退出程序」按钮，那才是真正退出。
  勾选「开机自动启动」后，登录 Windows 就会后台启动并按上次状态继续分拣。

【规则怎么写】

  点「编辑规则」会用记事本打开规则文件，默认位置：
      C:\Users\<你>\AppData\Roaming\PDFFolderMover\rules.txt

  一行一条，格式：  关键词 => 目标文件夹

      地铁1号线,停车场 => D:\监测日报\地铁1号线停车场
      城西路          => D:\监测日报\城西路
      跨江,隧道        => D:\监测日报\跨江隧道

  · 关键词可以写多个，用英文逗号或中文逗号分隔，命中任意一个就算匹配；
  · 不区分大小写；
  · 多条规则同时命中时，用关键词最长的那条（越具体越优先）；
    比如「隧道」和「城西路隧道」都命中，走「城西路隧道」那条；
  · 以 # 开头的行是注释；
  · 目标文件夹必须是已经存在的文件夹，否则该文件会被跳过并在日志里提示；
  · 保存后程序会自动检测到改动并重新加载，不用重启（也可以点「重新加载」）。

【为什么不会搬走"还没生成完"的文件】

  两道判断都在等，任一不满足就不动：

   1) 稳定性：文件大小和修改时间连续 N 秒（默认 3 秒）没有变化；
   2) 独占性：以"不允许任何程序共享"的方式尝试打开该文件。
      PDF 打印驱动、阅读器只要还占着它，打开就失败 —— 说明还没写完。

  两个条件都通过才会移动到目标文件夹。同盘移动是瞬时的改名操作，不复制、不改内容。

【其他细节】

  · 只认 .pdf（不分大小写），其他文件不碰。
  · 目标文件夹已有同名文件时，自动改名成「报告 (2).pdf」，绝不覆盖。
  · 默认只处理"启动之后新生成"的 PDF；源文件夹里原本就有的不动，
    需要连旧的也处理，勾选「启动时，把源文件夹里已经存在的 PDF 也按规则分拣一次」。
  · 状态栏会显示本次成功/失败/未匹配的数量，日志框里能看到每一份的去向。
  · 设置和日志：%APPDATA%\PDFFolderMover\
      config.json   设置
      rules.txt     分拣规则
      app.log       运行日志

【装好后建议先自检一次】

  命令行运行：  "PDF文件夹搬运助手.exe" --selftest

  它会在临时目录里模拟"创建 PDF → 边写边监听 → 写完 → 按规则分拣到两个不同项目文件夹"
  的完整过程，最后弹窗告诉你通过了几项。全程不碰你的真实文件夹。

  CI 里用无窗口版本： selftest.exe --selftest-console   （退出码 0=通过）

【自动更新（整包方式）】

  更新源已经内置在程序里（界面上不显示、也无法修改）。
  程序启动时自动检查（先自动开始分拣、再检查更新，两者互不影响），
  界面上没有"检查更新"按钮，检查结果只写在日志里。

   1. 读取 latest.json，比较版本号；
   2. 有新版本 → 弹窗询问 → 下载 zip 更新包；
   3. 校验包的大小和 sha256；
   4. 解压到临时目录，启动新版程序（--install-update）；
   5. 旧程序退出 → 新程序等旧进程真正结束（WaitForSingleObject，按 PID 精确等）
      → 把解压出来的文件覆盖到安装目录（你额外放的文件不会被删）
      → 启动新版，清理临时目录。

  发布新版本的做法（随包给了 发布新版本.py）：

     1. 改 update.go 里的 const appVersion，重新编译；
     2. python 发布新版本.py 1.2.3 "本次更新说明"
        → 生成 PDFFolderMover-v1.2.3.zip 和 latest.json
        → latest.json 里带 version / notes / package / package_size / package_sha256 / exe_name
     3. 把 zip 和 latest.json 传到同一个能直链下载的目录（程序里的地址写死）。

  没有服务器可以无视这一节 —— 不影响分拣功能。

【已知限制】

  · 本程序只做"分拣搬运"，不改 PDF 内容、不合并、不改名。
  · 某个 PDF 一直被别的程序占着（比如你在阅读器里开着它），它会一直等，
    日志里写「文件仍被占用，继续等待」——这是有意为之，不是卡死。
  · 只支持 Windows 10 / 11 64 位。
  · 卸载＝直接删掉 exe；开机自启动的开关记得先在界面里取消。
